# UC-05: Configure Measurement Streaming

## Objective

Define how the host enables, disables, or queries the **Continuous Measurement Streaming** mode through the standard communication interface.

## Requirements

| **ID**                         | **Description**                                                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| [**FR-01**](../FR/FR-01.md)    | The system shall support a standard byte-stream protocol for communication with the host.                         |
| [**FR-02**](../FR/FR-02.md)    | The system shall only accept messages over the standard communication interface if the message checksum is valid. |
| [**FR-10**](../FR/FR-10.md)    | The system shall allow the host to query the current measurement streaming state.                                |
| [**FR-11**](../FR/FR-11.md)    | The system shall allow the host to enable or disable continuous measurement streaming.                            |
| [**NFR-01**](../NFR/NFR-01.md) | The standard communication interface shall remain operational after receiving a corrupted or invalid message.     |
| [**NFR-03**](../NFR/NFR-03.md) | The system shall apply and store updated configuration parameters only if they are valid.                         |
| [**NFR-04**](../NFR/NFR-04.md) | Important configuration parameters shall be stored in non-volatile memory.                                        |
| [**NFR-05**](../NFR/NFR-05.md) | Boolean parameters shall be represented as unsigned 8-bit integers (`u8`), where `0` = *false* and `1` = *true*. |

## Actors

* **Host** – External controller or computer communicating with the device via the byte-stream protocol.

## Preconditions

* Device powered and communication interface operational.

## Entry Condition

* Host sends a valid message to read or modify the streaming mode.

## Main Flow

### Case 1: Read Streaming State

1. Host sends **Get Measurement Streaming State** request.
2. System validates and retrieves the current streaming state.
3. System sends the response message.
4. Host processes the result.

### Case 2: Set Streaming State

1. Host sends **Set Measurement Streaming State** request with new value.
2. System validates the message and value.
3. System updates and stores the configuration.
4. System acknowledges the change.
5. Host verifies acknowledgment.

## Alternate Flow

* If validation fails, the system discards the message and keeps the previous configuration.

## Post-conditions

* Streaming configuration updated and stored if valid.
* Device remains operational.

## Business Rules

1. Streaming mode controls whether the system transmits measurements automatically.
2. When enabled, after a measurement is finished and transmitted over the communication interface, another one is automatically started.
3. When disabled, the system will not automatically start a new measurement after the current one is finished.
4. Invalid values are ignored.
