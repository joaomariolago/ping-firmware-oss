# UC-04: Configure Scan Parameters

## Objective

Define how the host reads or writes the **Scan Start** and **Scan Length** parameters through the standard communication interface.
These parameters determine the range window (in millimeters) used during acoustic scans or measurements.

## Requirements

| **ID**                         | **Description**                                                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| [**FR-01**](../FR/FR-01.md)    | The system shall support a standard byte-stream protocol for communication with the host.                         |
| [**FR-02**](../FR/FR-02.md)    | The system shall only accept messages over the standard communication interface if the message checksum is valid. |
| [**FR-08**](../FR/FR-08.md)    | The system shall allow the host to query the current scan start and scan length parameters.                      |
| [**FR-09**](../FR/FR-09.md)    | The system shall allow the host to set new scan start and scan length parameters.                                |
| [**NFR-01**](../NFR/NFR-01.md) | The standard communication interface shall remain operational after receiving a corrupted or invalid message.     |
| [**NFR-03**](../NFR/NFR-03.md) | The system shall apply and store updated configuration parameters only if they are valid.                         |
| [**NFR-04**](../NFR/NFR-04.md) | Important configuration parameters shall be stored in non-volatile memory.                                        |

## Actors

* **Host** – External controller or computer communicating with the device via the byte-stream protocol.

## Preconditions

* Device powered and communication interface operational.
* Current scan parameters available in configuration.

## Entry Condition

* Host sends a valid message to read or write scan parameters.

## Main Flow

### Case 1: Read Scan Parameters

1. Host sends **Get Scan Parameters** request.
2. System validates the message and retrieves:
   * **Scan Start** (`u32`, millimeters)
   * **Scan Length** (`u32`, millimeters)
3. System sends a response message containing both values.
4. Host processes and stores the received values.

### Case 2: Set Scan Parameters

1. Host sends **Set Scan Parameters** request containing new `u32` values for **Scan Start** and **Scan Length** (mm).
2. System validates the message and checks that parameters are within valid operational range.
3. System updates and stores the new parameters.
4. System acknowledges completion.
5. Host verifies the acknowledgment.

## Alternate Flow

* If message validation or parameter range check fails, the system discards the message and keeps previous values.

## Post-conditions

* Updated scan parameters stored (persistent if supported).
* Device remains operational and ready for subsequent commands.

## Business Rules

1. **Scan Start** and **Scan Length** shall be represented as **unsigned 32-bit integers** (`u32`).
2. Units: **millimeters (mm)**.
3. Both parameters must define a valid scan window:
   * `Scan Start + Scan Length` shall not exceed the device’s maximum measurable range.
4. Invalid or out-of-range values shall not be applied.
