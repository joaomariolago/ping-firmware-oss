# UC-02: Configure Device ID

## Objective

Define how the host queries or assigns a **Device ID** through the standard communication interface. The Device ID uniquely identifies the device within a network or multi-device configuration.

## Requirements

| **ID**                         | **Description**                                                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| [**FR-01**](../FR/FR-01.md)    | The system shall support a standard byte-stream protocol for communication with the host.                         |
| [**FR-02**](../FR/FR-02.md)    | The system shall only accept messages over the standard communication interface if the message checksum is valid. |
| [**FR-04**](../FR/FR-04.md)    | The system shall allow the host to query the current Device ID.                                                   |
| [**FR-05**](../FR/FR-05.md)    | The system shall allow the host to set a new Device ID.                                                           |
| [**NFR-01**](../NFR/NFR-01.md) | The standard communication interface shall remain operational after receiving a corrupted or invalid message.     |
| [**NFR-03**](../NFR/NFR-03.md) | The system shall apply and store updated configuration parameters only if they are valid.                         |
| [**NFR-04**](../NFR/NFR-04.md) | Important configuration parameters shall be stored in non-volatile memory.                                        |

## Actors

* **Host** – External controller, ground station, or computer communicating with the device via the byte-stream protocol.

## Preconditions

* Device powered and communication interface operational.

## Entry Condition

* Host sends a valid message to read or write the Device ID.

## Main Flow

### Case 1: Read Device ID

1. Host sends **Get Device ID** request.
2. System validates and retrieves current **Device ID** (`u8`).
3. System sends response containing the Device ID.
4. Host processes the response.

### Case 2: Set Device ID

1. Host sends **Set Device ID** request containing a new `u8` value.
2. System validates the message.
3. System updates and stores the Device ID.
4. System acknowledges completion.
5. Host verifies the confirmation.

## Alternate Flow

* If message validation fails, the system discards it and keeps the current Device ID.
* If the new ID equals the existing one, system still confirms the request.

## Post-conditions

* Updated Device ID stored (persistent if supported).
* Communication remains operational.

## Business Rules

1. **Device ID** is an unsigned 8-bit integer (`0–255`).
2. A valid **Set Device ID** overwrites the previous one.
3. Subsequent communication includes the Device ID for addressing.
