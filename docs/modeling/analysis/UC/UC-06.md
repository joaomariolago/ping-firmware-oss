# UC-06: Configure Automatic Mode

## Objective

Define how the host enables, disables, or queries the **Automatic Configuration Mode** through the standard communication interface.
When enabled, the device autonomously adjusts scan start, scan length, and TX/RX gains based on bottom lock, reacquisition, SNR, and other environmental factors.

## Requirements

| **ID**                         | **Description**                                                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| [**FR-01**](../FR/FR-01.md)    | The system shall support a standard byte-stream protocol for communication with the host.                         |
| [**FR-02**](../FR/FR-02.md)    | The system shall only accept messages over the standard communication interface if the message checksum is valid. |
| [**FR-12**](../FR/FR-12.md)    | The system shall allow the host to query the current automatic configuration mode state.                          |
| [**FR-13**](../FR/FR-13.md)    | The system shall allow the host to enable or disable automatic configuration mode.                                |
| [**NFR-01**](../NFR/NFR-01.md) | The standard communication interface shall remain operational after receiving a corrupted or invalid message.     |
| [**NFR-03**](../NFR/NFR-03.md) | The system shall apply and store updated configuration parameters only if they are valid.                         |
| [**NFR-04**](../NFR/NFR-04.md) | Important configuration parameters shall be stored in non-volatile memory.                                        |
| [**NFR-05**](../NFR/NFR-05.md) | Boolean parameters shall be represented as unsigned 8-bit integers (`u8`), where `0` = *false* and `1` = *true*. |

## Actors

* **Host** – External controller or computer communicating with the device via the byte-stream protocol.

## Preconditions

* Device powered and communication interface operational.

## Entry Condition

* Host sends a valid message to read or modify the automatic configuration mode state.

## Main Flow

### Case 1: Read Automatic Mode

1. Host sends **Get Automatic Mode** request.
2. System validates and retrieves the current automatic mode state.
3. System sends a response message containing the state value.
4. Host processes the response.

### Case 2: Set Automatic Mode

1. Host sends **Set Automatic Mode** request with a new `u8` value (`0` or `1`).
2. System validates the message and value.
3. System updates and stores the new configuration.
4. System acknowledges completion.
5. Host verifies the acknowledgment.

## Alternate Flow

* If message validation fails, the system discards the message and retains the previous configuration.

## Post-conditions

* Updated automatic configuration mode stored (persistent if supported).
* Device remains operational and ready for subsequent commands.

## Business Rules

1. **Automatic Configuration Mode** determines whether the device autonomously adjusts scan and gain parameters.
2. Invalid or undefined values shall be ignored.
